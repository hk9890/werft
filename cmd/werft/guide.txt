werft - a guide for agents

A werft lease is a disposable VM on this host. Install and test software in
it, then give it back. Release destroys the VM; nothing you do in it reaches
the stock image or the host.

Rules:
- Release every lease when you are done, also after a failure.
- Use only werft images, lease, leases, extend, release, reap, guide and
  help. Never run werft start, stop, reset, snapshot, seal, provision,
  prepare or migrate: they change the user's build VMs.
- Use werft images only to list the stock versions. Never run
  werft images --prune: it deletes the user's old stock versions.
- Never touch a VM that is not your lease. The one exception is reap: it
  removes only expired leases and orphans, the same pass that every lease
  command runs first.
- Add --json to every command. stdout then holds one JSON document;
  progress goes to stderr.
- Give every lease an --owner that is unique to you, such as your session
  or task name. The owner is how you find your lease again.

1. Find an image

    werft --json images

  Each entry has "image" and "tier". Tier "plain" is the vendor install
  with SSH and nothing more. Tier "full" is the user's full setup, with the
  user's secrets; use it only when the task needs that setup. An entry with
  "luks": true has an encrypted disk: its lease reads the disk password
  from pass, so it needs the user's GPG agent unlocked.

2. Lease a VM

    werft --json lease ubuntu-26-04 --tier plain --owner <your-name>

  The command returns when the VM accepts SSH. An encrypted image first
  waits up to 3 minutes for its disk password prompt. Then it waits up to
  5 minutes for an address and then up to 5 minutes for SSH, plus the time
  of each attempt and the wait for the lock of other lease calls. Give the
  call a timeout of at least 20 minutes, or run it in the background and
  wait for it. The id comes only in the JSON document at the end.

  If the call was killed or its output is lost, find your lease by its
  owner in the output of werft --json leases and release it.

  The default tier is plain. The VM gets the memory, the vCPUs and the
  stock version of the newest stock image, and lives 4 hours. Change them
  with these flags:

    werft --json lease ubuntu-26-04 --owner <your-name> --memory 8192 --cpus 4 --for 2h
    werft --json lease ubuntu-26-04 --owner <your-name> --stock ubuntu-26-04-plain-20261102

  --memory is in MiB, at least 256. --cpus is at least 1. --for is from
  15m to 24h. --stock takes a "name" of werft --json images; it must be of
  the image you lease. Without --tier, the lease takes the tier of that
  version; with --tier, the version must be of that tier. More memory can
  fail with no_capacity.

  The JSON document has these fields:

    id          the lease id; every other command takes it
    domain      the VM name
    image       the image name
    tier        plain or full
    stock       the stock image version
    owner       the --owner flag, else $WERFT_OWNER, else $USER
    state       running, or a libvirt state such as shut off or paused
    user        the login user in the VM
    address     the SSH address, such as vsock/3; empty when not running
    key         the path of the private key of the lease
    ssh_config  the path of the ssh_config of the lease
    ssh         the ssh command, such as: ssh -F <ssh_config> <id>
    created     the creation time (RFC 3339)
    expiry      the expiry time (RFC 3339)

  A lease that fails cleans up after itself. If its error message names
  werft release <id>, run that command. Then try the lease once more.
  If the second lease fails too, give the user the error message. When
  the last screen of the VM was saved, the message names its file.

3. Run commands in the VM

  Append the command to the "ssh" value. One command per ssh call; it
  needs no terminal and asks no question:

    ssh -F <ssh_config> <id> 'uname -a'

  The user has passwordless sudo. Use sudo -n, so a missing grant fails at
  once and does not wait for a password. The image is minimal: install what
  you need, and update the package lists first:

    ssh -F <ssh_config> <id> 'sudo -n apt-get update && sudo -n apt-get install -y curl'

  In tier full, the user's tools load only in an interactive login shell
  of the user. Run the command through it:

    ssh -F <ssh_config> <id> '$SHELL -ic "mise ls"'

4. Move files and reach ports

  The ssh_config also works for scp, tar and port forwards. Copy a
  directory in, then a file out:

    tar -C <dir> -cf - . | ssh -F <ssh_config> <id> 'mkdir -p src && tar -C src -xf -'
    scp -F <ssh_config> <id>:src/result.log .

  Start a server in the VM with its input and output detached, or the ssh
  call does not return:

    ssh -F <ssh_config> <id> 'nohup python3 -m http.server 8080 </dev/null >/dev/null 2>&1 &'

  To reach a port in the VM, such as that web server on port 8080, forward it
  from a free local port. Other agents may forward ports too, so pick a
  port of your own, such as 18080. With -f the forward runs in the
  background once it is up; ExitOnForwardFailure makes ssh fail when the
  local port is taken:

    ssh -F <ssh_config> -f -N -o ExitOnForwardFailure=yes -L 18080:localhost:8080 <id>

  Then use http://localhost:18080. The forward ends when the VM reboots.

5. Reboot and power off

  The VM may reboot (sudo -n systemctl reboot): the lease keeps its id and
  its ssh command. Try the ssh command every 5 seconds for up to 5 minutes;
  if it does not answer by then, release the lease. Start a port forward
  again after the reboot.

  Do not power the VM off. You may not start a lease again, and a started
  lease can get a new address that its ssh command does not know. Release
  it and take a new lease.

  werft --json leases shows the state of each lease. A lease that is not
  in state running has no address: release it and take a new lease.

6. Watch the time

  A lease lives 4 hours, or the --for of the lease call. No timer
  destroys it: the first werft lease, leases, extend, release, reap or
  images --prune after the expiry does. Add time before the expiry:

    werft --json extend <id> --for 2h
    werft --json leases

  The leases command lists the leases of this user's state directory:
  yours and those of other agents that share it, with id, owner, image,
  tier, state, address and expiry. An expired lease is gone: extend fails
  with not_found.

7. Release the lease

    werft --json release <id>

  Release is idempotent: a second release of the same id exits 0. If a
  release fails, run it again.

Exit codes:
  0   ok
  1   failed              unexpected libvirt or SSH error; read the message
  2   usage               wrong command, flag or argument; run werft help <command>
  3   not_found           no such image, tier or lease; run werft --json images or leases
  4   conflict            a VM is not shut off, or a name exists
  5   needs_confirmation  the command needs --yes; agent commands never do
  6   no_capacity         not enough host memory or disk for a new lease;
                          release a lease of yours, or wait and try again
  7   timeout             no SSH, no address or no libvirt answer in time;
                          after a lease, follow "A lease that fails" above;
                          after a release, run the release again
  8   checks_failed       the provision checks failed
  9   unsupported         the image cannot be leased; take another image
  10  secret_unavailable  a secret is not available without a terminal; an
                          encrypted image needs its disk password from pass:
                          ask the user to unlock the password store, for
                          example by running pass show <entry> once (the
                          error names the entry), then lease again; never
                          print the password or ask for it yourself

On error, the --json document is:
  {"error": {"kind": "<kind>", "message": "<text>"}}
